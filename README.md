# 3D Printer Calibration via a Camera-Based Virtual Encoder

Calibration of the motion axes of a 3D printer (**steps/mm**, **backlash**, and
**XY skew / orthogonality**) **without a dial indicator and without an encoder** - using a
single camera and a chessboard target as a *virtual encoder*. The result is validated by
running an elliptical toolpath and measuring the deviation from ground truth.

> **Start here:** [`docs/00_PANDUAN.md`](docs/00_PANDUAN.md) - a step-by-step handoff
> guide with the expected output of every stage. *(The `docs/` files are written in
> Indonesian; the code, this README, and all outputs are in English.)*

---

## Key Results

**Machine calibration** (linear test, 10 mm commanded move, 10 valid samples out of 40 trials):

| Metric | Baseline | After calibration | Improvement |
|---|---|---|---|
| X axis error | 0.0463 mm | 0.0071 mm | 84.7 % |
| Y axis error | 0.0550 mm | 0.0054 mm | 90.2 % |
| Y drift while moving X | 0.0937 mm | 0.0043 mm | 95.4 % |
| X drift while moving Y | 0.0898 mm | 0.0036 mm | 96.0 % |

Starting parameters: steps/mm X 80, Y 80; backlash comp 0; skew comp 0.
Final parameters: steps/mm X 79.72, Y 80.40; backlash X 13.3 µm, Y 31.4 µm;
skew -9.2 µm/mm (X-on-Y), 9.213 µm/mm (Y-on-X) - about ±0.52°.

**Elliptical toolpath evaluation** (RMSE against ground truth):

| Metric | Baseline | After calibration |
|---|---|---|
| RMSE X | 76.91 µm (std 5.33) | 34.42 µm (std 1.61) |
| RMSE Y | 65.29 µm (std 4.67) | 30.75 µm (std 1.30) |
| **RMSE total** | **100.89 µm** (std 7.00) | **46.17 µm** (std 1.68) |

**Total trajectory accuracy improvement: 54.24 %.** Every number above was regenerated by
re-running the notebooks in this repository, not copied from the thesis manuscript.

**About the final values - important.** 79.72 / 80.40 is not the result of a single
calculation. The calibration is an **iterative loop**: each round, the newly recommended
parameters are written back into the machine, a fresh dataset is captured, the error is
measured again, and so on until the error **stops moving (steady state)** and has fallen to
the order of the measuring instrument's own *measurement error*.
The chain: 80.00 (baseline) -> 79.6314 (round-1 recommendation) -> several intermediate
rounds -> **79.72 (final)**. So if you run the notebooks on the included dataset and get a
recommendation of 79.6314, that is **not a bug** - it is round one, not the final value.
Full procedure: [`docs/00_PANDUAN.md`](docs/00_PANDUAN.md) Step 2b.

**Measurement error** (validation against a dial indicator, 0.5 mm commanded move,
5 iterations): the mean absolute difference between the virtual-encoder reading and the
dial indicator is **4.96 µm** (X axis combined) and **7.81 µm** (Y axis combined) - inside
the ±10 µm resolution of the dial indicator itself.

## Pipeline

```
 [1] CAMERA calibration
     EDLines -> line screening -> subpixel corner refinement -> corner sorting (homography)
     -> cv2.calibrateCamera -> intrinsic matrix K + distortion coefficients D
     (output: data/processed/camera_calibration/*.csv)
                     |
                     v
 [2] MACHINE calibration (per-axis linear test)
     Dataset from otomasi_pengujian_linear.py, starting parameters 80/80/0/0
     -> solvePnP per image -> dX/dY, backlash, skew
     -> firmware recommendations M92 (steps/mm), M425 (backlash), M852 (skew)
                     |
                     v
 [2b] Apply the recommendation, capture a new dataset, measure again
      -> repeat until the error reaches steady state
                     |
                     v
 [3] Run the elliptical toolpath with the new parameters
     -> record video of the calibrated toolpath (baseline toolpath recorded earlier)
                     |
                     v
 [4] Virtual Encoder
     Every video frame: detect the target -> solvePnP -> tvec
     -> position relative to the first valid frame -> trajectory X(t), Y(t) in mm
     -> export CSV
                     |
                     v
 [5] Trajectory evaluation
     Ground truth = 2 intersecting ellipses (45 deg and 135 deg), forward + backward
     Nearest neighbour (cKDTree) -> RMSE X, Y, total in micrometres (µm)
     Baseline vs calibrated -> percentage improvement

 [6] Measurement error (separate experiment, validated with a dial indicator)
     Baseline parameters, commanded move reduced to 0.5 mm
     -> compare the virtual-encoder reading against the dial indicator
```

## Running

```bash
pip install -r requirements.txt
python config_paths.py          # check that every dataset is found
```

`cv2.ximgproc` (`EdgeDrawing`) is **only available in `opencv-contrib-python`**, not in
plain `opencv-python`. Versions used in this research: Python 3.11.9,
opencv-contrib-python 4.12.0.88, numpy 2.2.6, scipy 1.17.1, pandas 3.0.2,
matplotlib 3.10.8.

Run each notebook **from inside its own folder** so that `config_paths.py` at the repo root
can be found.

Pick the test mode with an environment variable, without editing any notebook:

```bash
set KALIBRASI_MODE=baseline        # Windows   (baseline | calibrated | measurement_error)
export KALIBRASI_MODE=baseline     # Linux / macOS
```

| Mode | Dataset | steps/mm | target |
|---|---|---|---|
| `calibrated` (default) | `linear_calibrated_x/y` | 79.72 / 80.40 | 10 mm |
| `baseline` | `linear_baseline_x/y` | 80 / 80 | 10 mm |
| `measurement_error` | `measurement_error/*_machine_movement` | 80 / 80 | 0.5 mm |

Detailed per-stage instructions, expected outputs, and known limitations are in
[`docs/00_PANDUAN.md`](docs/00_PANDUAN.md).
